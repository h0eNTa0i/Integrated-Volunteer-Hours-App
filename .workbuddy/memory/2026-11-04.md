## 数据读取真实性核查与修复

- 用户质疑：数据分离成 data.json 后，程序是否真正读取了它。
- 核查结论（改造前）：`loadData()` 为「fetch('data.json') 优先、失败静默回退内嵌 `<script id="data-fallback">` 副本」。在单文件预览/双击打开 HTML 时 fetch 必然 404，程序实际读的是内嵌副本，而非 data.json 文件本身——用户的质疑成立。
- 修复：
  - 三端（student/publisher/admin.html）批量加入「数据来源」标识：`loadData()` 写入 `window.__dataSource`（'data.json' 或 'fallback'）；新增 `markDataSource()` 在侧栏副标题下显示绿色「✓ 数据来源：data.json」或橙色「⚠ 未读到 data.json，使用内置兜底」。
  - 新增 `server.js`（node 极简静态服务器，绑定 127.0.0.1:8787，服务 frontend 目录），`node server.js` 启动后通过 HTTP 访问，`fetch('data.json')` 真正生效。
- 验证：curl 确认 http://127.0.0.1:8787/data.json 返回 200；三端 JS 语法通过；markDataSource/dataSourceBadge/__dataSource 齐全。
- 结论/用法：要程序真正读取 data.json，需经 HTTP 服务器访问（`node server.js` 或任意静态服务器）；直接双击 HTML 会因 fetch 失败走内嵌兜底（此时标识会显示橙色警告）。

## 兜底副本漂移问题——彻底移除 fallback

- 用户改 data.json（activities[0].location 改为「东区原神场」）后程序未反映新数据。
- 根因：三端 HTML 内嵌的 `data-fallback` 副本仍是旧快照（「东区田径场」），与 data.json 漂移；程序走 fallback 时读到旧数据。
- 修复（彻底消除两份数据）：
  - 删除三端内嵌 `data-fallback` 副本，`data.json` 成为唯一数据源。
  - `loadData()` 改为 fetch 失败返回 `null`（不再读副本）；`init()` 遇 null 显示「数据加载失败」提示 + 引导用 `node server.js` 访问。
  - `markDataSource()` 三态：data.json（绿）/ error（橙「请通过服务器访问」）。
  - `server.js` 响应头加 `Cache-Control: no-store`，重启生效，确保刷新即读最新数据。
- 验证：三端兜底副本残留=false、JS 语法 OK；服务器返回 data.json 的 a1.location 为「东区原神场」，响应头含 no-store。
- 约定：改数据只改 `data.json`，经 HTTP 访问即生效；直接双击 HTML 会显示加载失败提示（需服务器）。

## data.json 加注释（JSONC 格式）

- 需求：在 data.json 里加注释，标注哪些数据对应哪个端。
- 方案：标准 JSON 不支持注释，改为 JSONC（带注释 JSON）格式：`data.json` 顶部及各块加入 `//` 行注释 + `/* */` 说明，标注「学生端 / 发布者端 / 校方管理端」及每个字段/页面用途。
- 程序侧：三端 `loadData()` 改为 `fetch → r.text() → stripJsonComments(text) → JSON.parse`；新增 `stripJsonComments()` 状态机（正确跳过字符串内的 // /* 与转义，处理行注释/块注释）。
- 验证：JSONC 剥离注释后 JSON.parse 成功，字段完整（activities 6 条、admin.auditLogs 3 条）；三端 JS 语法通过；服务器 200 返回带注释版本。
