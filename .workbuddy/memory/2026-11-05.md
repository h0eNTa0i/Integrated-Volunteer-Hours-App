## 修复 start_server.bat 中文乱码

- 现象：双击 bat 报「'闈掔瀵蹇楁効' 不是内部或外部命令」等一堆乱码，且被当成命令执行。
- 根因：bat 用 UTF-8 写中文，但 Windows cmd 默认按 GBK(936) 读取 .bat，导致中文乱码、多字节被拆成伪命令。
- 修复：用 Python 以 GBK(cp936) 编码重写 start_server.bat，顶部 `chcp 936 >nul`；app.py 启动 print 改为纯英文 `[QingHe Volunteer] ...` 避开控制台编码坑。
- 验证：依赖检查命令 OK、8787 端口已释放、bat 头字节确认 GBK 解码成功。
- 经验：Windows .bat 含中文必须用 GBK 编码写，不能 UTF-8；或干脆纯英文。

## 修复 MySQL 启动失败（start 命令拉不起 mysqld）

- 现象：用户双击 start_server.bat 后，后端报 `pymysql OperationalError 2003 Can't connect to MySQL`（MySQL 没起来）。
- 排查：MySQL 未监听 3306、无 mysqld 进程。发现关键——`start "MySQL" /min "...mysqld.exe" --console`（正斜杠路径 + --console）无法可靠拉起 mysqld；而 `mysqld --defaults-file=...my.ini`（不带 --console）能正常启动（错误日志显示 ready for connections）。
- 结论：`--console` 标志 + 分离式启动会失败；应改用 `--defaults-file`（不带 --console）+ 反斜杠路径。
- 修复三处：
  1. `db.py`：新增 `_mysql_connect()` 带 15 次重试（约15秒），MySQL 启动慢时后端不会崩，给出清晰报错。
  2. 新建 `start_mysql.bat`（GBK）：`cd /d "...\bin"` + `mysqld.exe --console` 前台运行（最可靠，窗口保持打开）。
  3. 重写 `start_server.bat`（GBK）：反斜杠路径 + `--defaults-file` 启动 mysqld + `findstr LISTENING` 过滤误判。
- 验证：MySQL 就绪、数据持久化（李四 id=1 仍在）、新注册王五写入 MySQL（id=2）、health=mysql、登录/注册全通。

## hours 字段统一数值返回（Decimal→float）

- 现象：MySQL 的 DECIMAL 列经 pymysql DictCursor 返回 Decimal，jsonify 序列化成字符串（如 "6.0"），而 SQLite 的 REAL 原生就是 float，两引擎不一致。
- 修复：db.py 顶部 `from decimal import Decimal`；加 `_to_py(v)`（Decimal→float，其余原样）；`_rows_to_dicts` 改为逐值 `_to_py` 转换。一处全局转换，所有 DECIMAL 字段（volunteer_hours.hours、certificates.hours）统一返回数值，id 仍 int。
- 验证（MySQL）：签退返回 hours=6.0(float)、hours/mine hours=6.0(float)、证书 hours=6.0(float)、id=int。SQLite 引擎天然 float 不受影响。
- 坑（第四次，同根因）：验证时 health 返回 sqlite 是又遇到残留 sqlite 后端（PID 23812，23:17 起）占 8787；杀所有 python 进程后干净重启，engine=mysql 才正确。教训：本项目「多 python 进程抢 8787」反复出现，验证前必须先 `Get-Process python | Stop-Process` + netstat 确认。

## 修复「取消报名后前端仍显示已报名」+ 同类数据同步隐患排查

- 现象：报名→取消报名后，前端活动仍显示「已报名」，怀疑数据库与前端不同步。
- 根因（两层）：
  1. **后端真实 bug**：signups 表有 UNIQUE(activity_id,user_id)，取消报名是软删除（status='cancelled'），记录仍占唯一约束，导致取消后**无法重新报名**（signup 里查到记录直接返回 11002）。
  2. **前端数据脱节**：s23「我的活动」用 test_data.json 静态 myActivities（与真实报名无关）；s2 详情页按钮固定「立即报名」无已报名状态；s1 活动列表 loadData 只在 init 拉一次、操作后不刷新；openMyActivity 依赖静态 signedIn 判断签到。
- 后端修复（app.py）：
  - signup()：查 existing 时区分——active 返回 11002；cancelled 恢复为 active（先原子扣名额再 UPDATE status），实现「重新报名」。
  - my_signups()：SELECT 补 gradient/scope/category/date 字段，供前端渲染真实活动卡片。
- 前端修复（index.html）：
  - 新增全局 `mySignups`/`myCheckinMap` + `refreshMyState()`（并行拉 signups/mine + checkins/mine）+ `renderMyActivities()` + `updateDetailSignupBtn()` + `refreshActivities()`。
  - s23 改为空容器 `<div id="myActivityList">` 动态渲染真实报名数据（状态标签：已报名/已签到/已结束）。
  - s2 详情页按钮加 id=detailSignupBtn，按 mySignups 切换「立即报名」/「已报名·取消报名」。
  - doSignup/doCancelSignup/signedIn/signedOut 成功后 await refreshMyState() + refreshActivities()；doLogin/doRegister 成功后 refreshMyState；logout 清空状态。
  - openMyActivity 重写：用 mySignups[i] + myCheckinMap 判断（已签退→结束提示、已签到→s17、未签到→s4），去掉静态 signedIn。
