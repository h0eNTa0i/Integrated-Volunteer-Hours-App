# 功能增量规格：志愿招募「发布与编辑管理」

> 产品：「志愿时长认证与活动管理」App（中国大学生）
> 增量范围：组织者侧「发布志愿招募 + 发布后编辑管理」能力的补全与强化
> 与既有 PRD 关系：本规格**扩展并部分替代**原 R11「模板化发布」，新增 R21 起编号需求
> 上游依据：用户研究（瑞思）、竞品分析（竞析）、数据（数析）三份产出，本规格直接引用，不重复研究

---

## 1. 功能定位与目标

**一句话定位**：让组织者「敢发布、敢修改、改得有规矩」——用表单工具级的编辑自由 + 活动系统的状态规范 + 即时自动通知，补上现有 PRD 在供给侧「发布后纠错闭环」的缺口。

### 三个正交目标

| # | 目标 | 说明 | 与北极星的关系 |
|---|------|------|----------------|
| G1 | **放大供给数量** | 通过模板复用 + 草稿箱 + 预填智能提示，降低单次发布成本，让非专业组织者更频繁、更规范地发布招募 | 活动数↑ = 可认证时长供给量↑，直接推高北极星「月活跃认证时长」的分母（供给端） |
| G2 | **形成信息纠错闭环** | 发布后允许编辑（分级 + 二次确认 + 留痕 + 自动通知），纠正错误而非"撤销重发"，减少组织者的挫败与信息失真 | 满员率↑、取消率↓、编辑响应时效↓，让"已发布但信息错了"的活动转化为有效供给而非流失 |
| G3 | **建立信任与合规留痕** | 分级权限 + 版本记录 + 审计日志 + 通知回执，满足组织者"向上级留痕、对已报名学生负责"的合规诉求 | 降低因错改/漏通知引发的申诉与纠纷，保护认证时长的可信度（北星指标的"质量"侧） |

> 三者正交：G1 解决"发得少"，G2 解决"发错了改不动"，G3 解决"改的过程可被信任"。任缺其一，编辑能力都会退化为"可以乱改"或"不敢改"。

## 2. 用户故事（验收导向）

> 覆盖：发布、编辑（人数/时间地点/时长/取消/岗位/截止）、留痕合规。

**US1（发布 + 模板）**：作为青协干部（组织者），我希望能基于上次活动的模板一键创建同类招募，只需改时间地点即可发布，这样每周一次的例行活动不再重复填 15 个字段。
- 验收：选择模板后，除时间外字段全部预填；从模板到发布 ≤ 3 步、≤ 2 分钟。

**US2（编辑人数）**：作为组织者，活动发布后报名火爆满员，我希望能把人数上限从 30 提到 50，系统自动通知候补学生并释放名额。
- 验收：提高上限即时生效；候补队列中前 N 名自动收到可报名通知；操作留痕。

**US3（编辑时间/地点）**：作为组织者，活动因天气改期，我希望能修改时间地点，系统强制通知所有已报名学生并要求回执确认，让我知道谁已知晓。
- 验收：改期需二次确认；保存后触发强制通知；未读/未回执学生可被组织者看到并二次触达。

**US4（更正时长，敏感）**：作为组织者，我把"志愿时长 4 小时"错填成"40 小时"，发布后才发现，我希望能下调修正；系统对未签到的报名者强制通知+二次确认，对已签到/已认证者锁定，防止数据被随意篡改。
- 验收：下调时长触发强制通知+二次确认；已签到学生的时长记录锁定不可被该次编辑覆盖；如需改已认证数据走校方审批。

**US5（取消活动，留痕）**：作为组织者，活动临时取消，我希望能一键取消并通知全员，但保留活动记录与报名名单作为"留痕"，而不是物理删除。
- 验收：取消后全员收到通知；活动记录进入"已取消"状态仍可查看、不可再报名；取消原因与当时报名人数留档。

**US6（权限 + 审计）**：作为校方管理员，我希望能查看任一活动的所有编辑历史（谁、何时、字段 X→Y、是否通知），以支撑合规审查与争议处理。
- 验收：每条编辑产生不可篡改审计日志；校方管理员可按活动/组织者检索版本记录。

## 3. 用户研究洞察（来自瑞思）

### 3.1 发布痛点 TOP5
1. 字段多无模板，易填错（时长单位、日期格式）。
2. 时长/人数怎么定没底，缺乏参考。
3. 重复发布同类活动费时。
4. 活动状态管理混乱（满员无法快速停止、变更只能另发群公告）。
5. 缺留痕，难向上级合规。

### 3.2 六个编辑场景及对已报名学生的影响与处理规则

| 场景 | 影响等级 | 处理规则 |
|------|---------|---------|
| 1 临时增加名额 | 正向 | 静默生效 + 广播给候补 |
| 2 调整时间/地点 | 高 | 强制通知 + 回执确认 |
| 3 更正时长写错 | 敏感 | 下调强制通知 + 二次确认；已签到则锁定 |
| 4 活动取消 | 极高 | 全员通知 + 不删记录留痕 |
| 5 岗位调整 | 中 | 通知受影响岗位者，引导重选 |
| 6 报名截止/门槛调整 | 中 | 区分「暂停」vs「满员」两种状态语义 |

### 3.3 功能期望与关键规则
- **功能期望**：草稿箱、模板复用、编辑留痕/版本记录、高敏感字段二次确认 + 展示影响范围（"将通知 N 名已报名学生"）、人数减少通知、活动开始后锁定核心字段、发布前预览、预填与智能提示。
- **编辑权限** = 发布者本人 + 同组织管理者 + 校方管理员（全程留痕）。
- **时间窗**：活动开始前可编辑（高风险字段二次确认 + 通知）；活动开始后锁定核心字段（时长/人数/岗位/签到方式），仅可改说明性字段；确需改走校方审批。
- **通知三档**：
  - 强制通知 = 时间 / 地点 / 取消 / 时长下调 / 人数减少
  - 轻量通知 = 时长上调 / 岗位新增 / 说明性变更
  - 无需通知 = 错别字 / 润色
- **优先级建议**：P0 = 编辑留痕、高风险字段二次确认、时间地点取消强制通知、开始后锁定；P1 = 模板复用、草稿箱、通知分档、权限分层；P2 = 预览、预填智能提示、状态区分。

## 4. 竞品对比（来自竞析）

### 4.1 「发布后编辑能力」对比表

| 竞品 | 发布后编辑 | 改后自动通知 | 状态机 | 防超卖 | 时长编辑 | 审计/留痕 |
|------|-----------|-------------|--------|--------|---------|-----------|
| 到梦空间 | ≈撤销重发，审批繁琐 | 无 | 有（学分体系强绑定） | 有 | 禁区（绑学分） | 有（审批流） |
| 志愿汇 | 编辑受限 | 无 | 有 | 有 | 禁区（绑签到） | 部分 |
| 问卷星/金数据 | 灵活（表单级） | 无 | 无活动状态机 | 无（可超卖） | 不适用 | 无 |
| 钉钉/企微 | 可改且改后自动通知（靠日历/会议基建） | ✅ 唯一做到 | 有（会议/日程） | 弱 | 不适用 | 有（日历审计） |
| 青协自建（群接龙/Excel） | 随意改、零通知 | 无 | 无 | 无 | 随意 | 无 |

**核心结论**：没有一家把"发布后编辑"做透——到梦繁琐、志愿汇受限且无通知、问卷星灵活但无状态机且超卖、钉钉有通知但无活动业务语义、自建全凭自觉。

### 4.2 差异化定位
> **"敢让组织者改、且改得有规矩"** = 编辑自由（对标表单）+ 状态规范（对标到梦/志愿汇）+ 自动通知（对标钉钉）。

### 4.3 六条关键设计启示（直接转化为需求）
1. 分级编辑权限：低风险字段随时改即时生效；高风险字段（名称/时间/地点/时长/人数）需二次确认 + 通知 + 留痕。
2. 人数上限调减防超卖：已报名 > 新上限时禁止直接生效，先处理超员或转候选。
3. 活动开始前 24h 锁定关键字段，展示"最后可改时间"倒计时。
4. 修改后自动通知已报名者（含差异高亮 + 退出报名入口）。
5. 版本记录 + 审计日志（谁 / 何时 / 字段 X→Y / 是否通知）。
6. 时长修改与签到解耦保护（历史已认证数据不可被普通编辑覆盖）。

## 5. 数据指标（来自数析）

### 5.1 试点口径
20 所高校 × 每校 6 个活跃组织者 × 3 个月（≈13 周）。

### 5.2 供给侧指标速览表（含参考值）

| 指标 | 参考目标 |
|------|---------|
| 活动发布数 | 周均 ≥ 2 / 校 |
| 发布者活跃率 | 首月 ≥ 30% → 第 3 月 ≥ 50% |
| 复发布率（30 日） | ≥ 40% |
| **活动编辑率** | 20%–40% |
| 编辑频率分布 | 中位数 1–2 次/活动；≥ 4 次 ≤ 15% |
| **编辑类型分布** | name < 10%（大头应是时间/人数/时长等纠错，非改名） |
| 编辑响应时效 | P50 ≤ 24h |
| 活动覆盖率 | 第 3 月 ≥ 80% |
| 单校活动密度 | ≥ 3 个/校 |
| 招募转化率 | 中位 ≥ 80% |
| 满员率 | 25%–45% |
| 活动取消率 | ≤ 5% |
| 认证时长供给量 | 随发布数线性增长（无硬阈值，看趋势） |
| 履约-认证衔接率 | ≥ 70% |

### 5.3 埋点事件

**activity_create**（含：organizer_role / title / duration_hours / headcount_limit / positions / location / event_time / signup_deadline / is_direct_publish / template_id? / draft_id?）

**activity_edit**（含：editor_role / field_name / old_value / new_value / edit_seq / time_since_publish；field_name 枚举：name / event_time / duration_hours / headcount_limit / position / location / signup_deadline / description）

**activity_cancel**（含：cancel_reason / enrolled_count_at_cancel）

辅助事件：activity_view / enroll / complete / hours_verified（用于算转化率、满员率、衔接率）。

> 一句话（数析）：发布放大供给数量、编辑形成信息纠错闭环（满员率↑ 取消率↓ 编辑时效↓），直接推高「认证时长供给量」，驱动北极星「月活跃认证时长」。

## 6. 需求池（新增需求，编号 R21 起）

> 与原 R11 关系标注：`扩展` = 在原「模板化发布」之上增量；`拆分` = 从 R11 语义中独立成新需求；`替代` = 重新定义 R11 边界（R11 保留为"名单导出 + 批量时长/证书"的运营侧能力，发布/编辑侧移交本组新需求）。

| 编号 | 需求 | 优先级 | 验收标准（Given/When/Then 摘要） | 估算（人日） |
|------|------|--------|----------------------------------|-------------|
| R21 | **发布表单与字段定义**（名称/时间/地点/时长/人数/岗位/报名截止/签到方式/描述/封面/联系方式/说明；时长单位、日期格式统一校验）｜`拆分`自 R11 | P0 | Given 组织者进入发布页，When 填表并提交，Then 字段校验通过方可发布；时长仅限整数/0.5 步进、日期须晚于报名截止、人数须为正整数；非法值即时红显并阻断 | 5 |
| R22 | **草稿箱**（保存草稿/恢复/删除，未发布前可反复编辑）｜`扩展` | P1 | Given 组织者编辑中途，When 点「存草稿」，Then 内容持久化可在草稿箱恢复；再次发布从草稿出发 | 3 |
| R23 | **模板复用**（从历史活动另存为模板、下次一键套用）｜`拆分`/强化自 R11 | P1 | Given 已有模板，When 选择模板创建，Then 除时间外字段预填，可改后发布；模板可新增/编辑/删除 | 4 |
| R24 | **发布后编辑：分级字段 + 二次确认 + 留痕**（低风险即时生效、高风险二次确认并展示影响范围）｜`替代` R11 中"发布即锁定"的隐含约束 | P0 | Given 活动已发布，When 编辑高风险字段，Then 弹二次确认并显示"将通知 N 名已报名学生"；保存后生成版本记录（谁/何时/X→Y） | 6 |
| R25 | **变更通知（分档 + 回执）**（强制/轻量/无需三档；差异高亮 + 退出报名入口；回执追踪）｜`扩展` | P0 | Given 编辑保存，When 变更属强制档，Then 全员已报名者收到通知且可回执确认；组织者可看未读/未回执名单并二次触达 | 5 |
| R26 | **活动取消**（一键取消、全员通知、保留记录留痕）｜`扩展` | P0 | Given 活动进行中，When 取消，Then 全员通知、状态置「已取消」、不可再报名、记录与名单保留可查、取消原因+当时报名数留档 | 3 |
| R27 | **活动状态机**（草稿/招募中/已满/报名截止/进行中/已结束/已取消，各状态限定可编辑操作）｜`扩展`（补全 R11 缺失的状态语义） | P0 | Given 活动处于某状态，When 组织者操作，Then 仅允许该状态白名单内的编辑/动作；非法操作置灰并说明原因 | 4 |
| R28 | **编辑权限分层**（发布者 + 同组织管理者 + 校方管理员；全程留痕）｜`扩展` | P1 | Given 非同组织且非发布者，When 尝试编辑，Then 无入口/被拒；校方管理员可编辑并强制留痕 | 4 |
| R29 | **活动开始后锁定核心字段**（时长/人数/岗位/签到方式锁定，仅改说明性字段；确需改走校方审批）｜`扩展` | P0 | Given 活动已开始，When 编辑核心字段，Then 被锁定并提示走校方审批；说明性字段仍可改 | 3 |
| R30 | **防超卖**（人数上限调减时，已报名 > 新上限则禁止直接生效，先处理超员或转候选）｜`扩展` | P0 | Given 已报名 45、新上限 40，When 提交调减，Then 被阻断，须先将 5 人转候补/退出后方可生效 | 3 |
| R31 | **审计日志**（不可篡改版本记录 + 检索）｜`扩展`（补齐合规留痕） | P0 | Given 任一编辑/取消发生，When 查询审计，Then 返回完整字段级变更链（谁/何时/X→Y/是否通知） | 4 |
| R32 | **发布前预览**（发布前所见即所得预览）｜`扩展` | P2 | Given 填表完成，When 点预览，Then 以学生视角渲染活动页，确认后再发布 | 2 |
| R33 | **预填与智能提示**（时长/人数建议、字段校验提示、错别字/格式纠错）｜`扩展` | P2 | Given 填表，When 输入存疑值，Then 提示参考区间与格式纠错（不阻断、可忽略） | 3 |

**与 R11 的最终关系**：R11 拆分为「发布表单(R21) + 模板(R23) + 状态机(R27)」，编辑/通知/取消/权限/锁定/防超卖/审计（R24–R31）为新增强化；R11 原"名单导出 + 批量时长/证书"仍保留在 R11 名下，不纳入本增量。

**估算合计**：约 49 人日（P0 约 37 人日，P1 约 11 人日，P2 约 5 人日）。

## 7. 活动状态机

```
                ┌────────────┐
    新建/存草稿 │   草稿     │◄──────── 编辑后存草稿
                └─────┬──────┘
                      │ 发布（校验通过）
                      ▼
             ┌─────────────────┐
             │  已发布 / 招募中  │◄──────── 编辑（低/高风险分级+通知）
             └───┬───────┬─────┘
       满员(报名≥上限)│       │ 报名截止时间到
                 ▼       ▼
           ┌────────┐ ┌────────────┐
           │  已满   │ │ 报名截止    │
           └───┬────┘ └─────┬──────┘
       名额释放/调增  │       │
                 ▼   ▼
             ┌─────────────┐
             │   进行中     │◄──── 核心字段锁定，仅改说明性字段
             └──┬───────┬──┘
        正常结束 │       │ 取消（任意招募/进行中状态可触发）
                 ▼       ▼
          ┌─────────┐ ┌─────────┐
          │  已结束  │ │ 已取消   │（记录保留，不可再报名）
          └─────────┘ └─────────┘
```

### 各状态允许的编辑操作（白名单）

| 状态 | 可编辑字段 | 可执行动作 | 禁止动作 |
|------|-----------|-----------|---------|
| 草稿 | 全部字段 | 存草稿、发布、删除 | — |
| 已发布/招募中 | 全部字段（分级 + 二次确认 + 通知） | 编辑、暂停报名、取消、调名额 | — |
| 已满 | 人数上限（增/减防超卖）、说明性字段 | 释放名额、转候补、取消 | 报名（面向学生） |
| 报名截止 | 说明性字段；确需改核心走审批 | 查看名单、取消 | 学生报名 |
| 进行中 | 仅说明性字段（描述/联系方式/说明） | 取消（走审批/留痕） | 时长/人数/岗位/签到方式/时间地点 |
| 已结束 | 不可编辑 | 导出名单、发时长/证书、归档 | 编辑、取消 |
| 已取消 | 不可编辑（只读留痕） | 查看记录、复制为新活动 | 报名、编辑 |

## 8. 字段与编辑分级规则表

### 8.1 发布字段清单

| 字段 | key | 类型 | 必填 | 校验 |
|------|-----|------|------|------|
| 活动名称 | name | 文本 | ✅ | 2–40 字 |
| 活动时间（起/止） | event_time | 日期时间 | ✅ | 起 < 止；晚于报名截止 |
| 地点 | location | 文本/POI | ✅ | 非空 |
| 志愿时长 | duration_hours | 数字 | ✅ | 整数或 0.5 步进，0.5–24h |
| 人数上限 | headcount_limit | 正整数 | ✅ | 1–10000 |
| 岗位（可多） | positions | 数组 | 否 | 岗位名 + 各岗位人数 |
| 报名截止 | signup_deadline | 日期时间 | ✅ | 晚于发布时间、早于活动开始 |
| 签到方式 | checkin_method | 枚举 | ✅ | GPS/二维码/双端（沿用 R4/R5） |
| 描述 | description | 富文本 | 否 | ≤ 2000 字 |
| 封面 | cover | 图片 | 否 | 尺寸/比例校验 |
| 联系方式 | contact | 文本 | 否 | 手机/微信/QQ 校验 |
| 补充说明 | notes | 文本 | 否 | ≤ 500 字 |

### 8.2 分级编辑规则

| 风险级 | 字段 | 活动开始前 | 活动开始后 | 二次确认 | 通知档 | 留痕 |
|--------|------|-----------|-----------|---------|--------|------|
| **高** | 名称 name | 可改（即时生效） | 锁定 | 可选 | 轻量 | ✅ |
| **高** | 时间 event_time | 可改 | 锁定 | ✅ | **强制** | ✅ |
| **高** | 地点 location | 可改 | 锁定 | ✅ | **强制** | ✅ |
| **高** | 时长 duration_hours | 可改（上调轻量/下调强制） | 锁定 | ✅ | 上调轻量 / 下调**强制** | ✅ |
| **高** | 人数 headcount_limit | 可改（增轻量/减防超卖+强制） | 锁定 | ✅ | 增轻量 / 减**强制** | ✅ |
| **中** | 岗位 positions | 可改 | 锁定 | 可选 | 新增轻量 / 调整强制（通知受影响者引导重选） | ✅ |
| **中** | 报名截止 signup_deadline | 可改 | 锁定 | ✅ | 视早于/晚于原截止（提前=强制/延后=轻量） | ✅ |
| **中** | 签到方式 checkin_method | 可改 | 锁定 | ✅ | 强制 | ✅ |
| **低** | 描述 description | 可改（即时生效） | 可改 | 否 | 无需 | ✅ |
| **低** | 封面 cover | 可改（即时生效） | 可改 | 否 | 无需 | ✅ |
| **低** | 联系方式 contact | 可改（即时生效） | 可改 | 否 | 无需 | ✅ |
| **低** | 补充说明 notes | 可改（即时生效） | 可改 | 否 | 无需 | ✅ |

**补充规则**：
- 时长修改与签到解耦：对**已签到/已认证**学生的时长记录，普通编辑不可覆盖；仅校方审批可改，且保留审计。
- 二次确认必须展示影响范围（"将通知 N 名已报名学生 / 影响 M 个岗位"）。
- 活动开始前 24h 内，高风险字段进入「倒计时提醒」态，展示"最后可改时间"。

## 9. 关键流程

### 9.1 发布流程

```
组织者进入发布页
  → 选择「空白新建」或「从模板创建」或「从草稿恢复」
  → 填写/编辑 12 字段（预填+智能提示辅助）
  → [可选] 存草稿 → 草稿箱
  → [可选] 发布前预览（学生视角）
  → 提交 → 字段校验
       ├─ 校验失败 → 定位红显、阻断
       └─ 校验通过 → 创建活动 → 状态=已发布/招募中 → 埋点 activity_create
```

### 9.2 编辑 + 二次确认 + 通知流程

```
组织者对「已发布」活动发起编辑
  → 判断字段风险级
       ├─ 低风险（描述/封面/联系方式/说明）
       │     → 直接保存 → 即时生效 → 留痕（无需通知）
       └─ 中/高风险（名称/时间/地点/时长/人数/岗位/截止/签到）
             → 活动是否已开始？
                  ├─ 已开始 → 核心字段锁定 → 提示走校方审批 → 结束
                  └─ 未开始 → 二次确认弹窗
                          （展示：字段 X→Y；影响范围"将通知 N 名已报名学生"）
                        → 确认保存
                        → 生成版本记录 + 审计日志（谁/何时/X→Y）
                        → 判断通知档（强制/轻量/无需）
                             ├─ 强制 → 全员已报名者收到通知（差异高亮 + 退出报名入口）
                             │          → 追踪回执，未读/未回执可二次触达
                             └─ 轻量 → 通知（无回执要求）
                        → 埋点 activity_edit（editor_role/field_name/old/new/edit_seq/time_since_publish）
                        → 涉及人数调减 → 防超卖校验（已报名>新上限则阻断，先转候补/退出）
```

### 9.3 取消流程

```
组织者对「招募中/已满/报名截止/进行中」活动发起取消
  → 填写取消原因（必填）
  → 二次确认（展示：将通知 N 名已报名学生 + 该操作不可逆）
  → 确认 → 状态置「已取消」
  → 全员强制通知（含取消原因）
  → 记录留痕：cancel_reason + enrolled_count_at_cancel 埋点 activity_cancel
  → 活动记录保留只读（名单/编辑历史仍可查），不物理删除
```

## 10. Non-goals（v1 明确不做）

1. **不改写历史已认证数据**：本次编辑能力作用于"招募信息"本身，不对已签到/已认证学生的时长做追溯重算；确需修正历史时长走独立校方审批流程（不在本增量）。
2. **不做组织者移动端完整后台**：v1 发布与编辑以 Web 管理后台为主；移动端仅提供只读查看与消息回执，不开放全量字段编辑。
3. **不做多人实时协同编辑 / 冲突合并**：权限解决"谁有权改"，不解决"同时改"；并发编辑采用"后写覆盖 + 版本留痕"而非协同锁。
4. **不做智能排期 / 场地冲突检测 / 自动推荐时间**：仅提供预填与格式校验（P2 智能提示是轻量辅助，非 AI 生成与排期）。
5. **不做支付/退款/积分流转**：活动取消不涉及任何资金或积分退转。
6. **不做活动取消后的自动"代报名补录"**：取消后学生需自行重新报名其他活动，系统不自动转移。
7. **不做对公众开放的对外分享预览链接**：预览仅登录组织者本人在发布前可见。

## 11. 待确认问题（开放问题，需向产品负责人/校方确认）

1. **校方审批触发门槛**：活动开始后"确需改走校方审批"，具体哪些字段、多大改动幅度（如时长下调 > 2h？人数减少 > 10%？）触发审批？审批人、审批流与 SLA 上限是多少？
2. **时长-签到解耦边界**：已报名但**尚未签到**的学生，时长下调是否仅需"强制通知+二次确认"即可，还是也必须校方审批？已签到学生的时长一旦认证/导出证书，是否彻底锁定？
3. **同组织管理者边界**：组织层级是「学校 / 学院 / 社团」三级吗？"同组织管理者"的继承规则（社团管理者能否编辑学院级活动）与审计归属如何定？
4. **防超卖的超员处置决策权**：人数调减导致超员时，是组织者手动选人转候补，还是系统按报名时间"后进先出"自动转候补？处理时限与对已转候补学生的通知口径？
5. **回执的强制性与时效**：时间/地点/取消的"回执确认"是否影响学生报名有效性？未回执学生组织者能否代为确认？回执截止时间（如 24h）由谁设定？
6. **通知渠道与成本**：强制通知是否必须短信/微信服务通知（成本），还是站内消息 + 推送即可满足"合规留痕"要求？校方对短信预算的额度？
7. **模板与草稿的生命周期**：模板/草稿的保留周期、单组织者容量上限？模板是否可跨组织共享（社团间共享模板）？
