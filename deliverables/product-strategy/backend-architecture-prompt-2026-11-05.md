## 一、项目背景

「青禾志愿」是一款面向中国大学生的志愿时长认证与活动管理 App（当前为 Web 高保真原型，前端为单文件 index.html）。核心闭环是「报名 → 签到 → 时长认定 → 证书导出」，解决志愿时长认定不透明、易漏记、证书不可验证的痛点。

定位：校园封闭生态 + 双角色（学生 / 发布者）+ 校方管理员。v1 仅面向本校在校学生，发布者可为校内或校外人员/机构，所有招募需经本校认可后方可计入志愿时长。

## 三、业务特征（决定架构形态的关键）

这是一款「强脉冲、季节性强并发」的应用，不是平稳流量：

1. **抢名额（秒杀式并发）**：热门活动释放少量名额，报名截止瞬间大量学生同时点击报名，存在「瞬时尖峰 + 防超卖」诉求（对应 R30）。需原子扣减名额、候补队列（R13）。
2. **签到/签退并发**：活动开始/结束时间点，参与学生集中 GPS/二维码签到签退（R4/R5/R8），短时写入密集。
3. **证书导出洪峰（年度级）**：综测季、评优/保研/入党材料提交前，学生集中查询时长、批量导出 PDF 证书（R7），属于典型的「读放大 + PDF 生成 CPU/IO 密集」。
4. **年度周期性**：每年学期末、奖学金评定、学年结束等固定节点，流量可数倍于平时，需能水平弹性扩容，平时可缩容控成本。

## 四、必须满足的非功能需求（重点）

请围绕以下三点给出「可量化、可验收」的设计（指标为参考值，可给出你的建议值并说明理由）：

### 高可用（High Availability）
- 全年可用性 ≥ 99.9%（允许给出更高目标及成本权衡）。
- 无单点故障：应用、数据库、缓存、消息队列均需冗余/主从/多可用区。
- 故障自动切换与降级：数据库主从切换、缓存击穿/雪崩防护、依赖降级。
- 数据安全：备份策略（全量+增量、PITR 时间点恢复）、容灾 RPO/RTO 目标。

### 高性能（High Performance）
- 核心读写接口 P95 延迟 ≤ 200ms，P99 ≤ 500ms。
- 数据库慢查询 < 100ms（核心查询）；常用读走缓存。
- 证书 PDF 生成、批量导出、消息通知等重任务异步化，不阻塞主链路。
- 冷热数据分离：历史时长明细/审计日志与热数据分表或归档。

### 高并发（High Concurrency）
- 报名（防超卖）：明确峰值 QPS 目标与削峰方案（令牌桶/漏桶限流、队列削峰、乐观锁或原子 UPDATE 扣减、Redis 预扣库存）。
- 查询：活动列表/时长查询走多级缓存（CDN + 本地缓存 + Redis），支撑平时 10× 的峰值。
- 签到：写入侧幂等 + 限流 + 缓冲（如先入 Redis/MQ 再异步落库）。
- 证书导出：异步任务队列 + 对象存储（OSS），避免同步生成 PDF 拖垮 API。

## 六、安全与合规（必含）

- 《个人信息保护法》《数据安全法》：学号、手机号、姓名、定位等敏感信息的最小化采集、静态加密存储、TLS 传输加密、脱敏展示、最小权限访问。
- 密码安全：bcrypt/argon2 哈希；防暴力破解（限流+锁定）。
- 接口安全：防 SQL 注入、XSS、CSRF、越权（水平/垂直越权校验）、防重放（签到/报名幂等）、动态二维码防截图。
- 审计：活动编辑、时长认定等关键操作只追加不更新、不可篡改（R31）。
- 数据隔离：单校数据隔离（v1），并为后续多校/多租户预留租户隔离方案。
