## 📌 TL;DR（执行摘要）

- **核心目标**：补全组织者侧「发布志愿招募 + 发布后编辑管理」能力，让组织者「敢发布、敢修改、改得有规矩」——用表单级编辑自由 + 活动系统状态规范 + 即时自动通知，补上供给侧「发布后纠错闭环」缺口。
- **关键决策**：新增需求 R21-R33（约 49 人日：P0 33 / P1 11 / P2 5）；供给侧基础（R21 发布、R27 状态机、R30 防超卖）**前置到 V1.0a** 与学生端 MVP 同期交付，纠错闭环（R24/R26/R29）放 V1.0b。
- **差异化**：竞品中无人做透「发布后编辑」——到梦繁琐、志愿汇受限无通知、问卷星灵活但无状态机且超卖；本产品做「分级编辑 + 二次确认 + 留痕 + 自动通知 + 防超卖」的组合。
- **下一步**：确认 7 项开放问题（校方审批门槛、时长-签到解耦边界、同组织管理者边界、超员处置、回执强制性与时效、通知渠道成本、模板草稿生命周期）。

## 1. 功能定位与目标

**一句话定位**：让组织者「敢发布、敢修改、改得有规矩」——用表单工具级的编辑自由 + 活动系统的状态规范 + 即时自动通知，补上现有 PRD 在供给侧「发布后纠错闭环」的缺口。

| # | 目标 | 说明 | 与北极星的关系 |
|---|------|------|----------------|
| G1 | **放大供给数量** | 模板复用 + 草稿箱 + 预填智能提示，降低单次发布成本，让非专业组织者更频繁、更规范地发布 | 活动数↑ = 可认证时长供给量↑，推高北极星分母（供给端） |
| G2 | **形成信息纠错闭环** | 发布后允许编辑（分级 + 二次确认 + 留痕 + 自动通知），纠正错误而非"撤销重发" | 满员率↑、取消率↓、编辑时效↓，减少供给流失 |
| G3 | **建立信任与合规留痕** | 分级权限 + 版本记录 + 审计日志 + 通知回执，满足组织者"向上级留痕、对已报名学生负责"的合规诉求 | 降低错改/漏通知引发的申诉，保护认证时长的可信度 |

> 三者正交：G1 解决"发得少"，G2 解决"发错了改不动"，G3 解决"改的过程可被信任"。

## 2. 用户故事（验收导向）

**US1（发布 + 模板）**：作为青协干部，我希望能基于上次活动的模板一键创建同类招募，只需改时间地点即可发布。
- 验收：选择模板后除时间外字段全部预填；从模板到发布 ≤ 3 步、≤ 2 分钟。

**US2（编辑人数）**：活动发布后报名火爆满员，我希望能把人数上限从 30 提到 50，系统自动通知候补学生并释放名额。
- 验收：提高上限即时生效；候补队列前 N 名自动收到可报名通知；操作留痕。

**US3（编辑时间/地点）**：活动因天气改期，我希望能修改时间地点，系统强制通知所有已报名学生并要求回执确认。
- 验收：改期需二次确认；保存后触发强制通知；未读/未回执学生可被组织者看到并二次触达。

**US4（更正时长，敏感）**：我把"志愿时长 4 小时"错填成"40 小时"，发布后才发现，需下调修正。
- 验收：下调时长触发强制通知 + 二次确认；已签到学生的时长记录锁定不可被该次编辑覆盖；改已认证数据走校方审批。

**US5（取消活动，留痕）**：活动临时取消，我希望能一键取消并通知全员，但保留活动记录与名单作为"留痕"。
- 验收：取消后全员收到通知；活动进入"已取消"状态仍可查看、不可再报名；取消原因与当时报名人数留档。

**US6（权限 + 审计）**：作为校方管理员，我希望能查看任一活动的所有编辑历史，支撑合规审查与争议处理。
- 验收：每条编辑产生不可篡改审计日志；校方管理员可按活动/组织者检索版本记录。

## 3. 用户研究洞察（来自瑞思）

### 3.1 发布痛点 TOP5
1. 字段多无模板，易填错（时长单位、日期格式）。
2. 时长/人数怎么定没底，缺乏参考。
3. 重复发布同类活动费时。
4. 活动状态管理混乱（满员无法快速停止、变更只能另发群公告）。
5. 缺留痕，难向上级合规。

### 3.2 六个编辑场景及处理规则

| 场景 | 影响等级 | 处理规则 |
|------|---------|---------|
| 1 临时增加名额 | 正向 | 静默生效 + 广播给候补 |
| 2 调整时间/地点 | 高 | 强制通知 + 回执确认 |
| 3 更正时长写错 | 敏感 | 下调强制通知 + 二次确认；已签到则锁定 |
| 4 活动取消 | 极高 | 全员通知 + 不删记录留痕 |
| 5 岗位调整 | 中 | 通知受影响岗位者，引导重选 |
| 6 报名截止/门槛调整 | 中 | 区分「暂停」vs「满员」两种状态语义 |

### 3.3 功能期望与关键规则
- **功能期望**：草稿箱、模板复用、编辑留痕/版本记录、高敏感字段二次确认 + 展示影响范围（"将通知 N 名已报名学生"）、人数减少通知、活动开始后锁定核心字段、发布前预览、预填与智能提示。
- **编辑权限** = 发布者本人 + 同组织管理者 + 校方管理员（全程留痕）。
- **时间窗**：活动开始前可编辑（高风险字段二次确认 + 通知）；活动开始后锁定核心字段（时长/人数/岗位/签到方式），仅可改说明性字段；确需改走校方审批。
- **通知三档**：强制通知 = 时间/地点/取消/时长下调/人数减少；轻量通知 = 时长上调/岗位新增/说明性变更；无需通知 = 错别字/润色。

## 4. 竞品对比（来自竞析）

### 4.1 「发布后编辑能力」对比表

| 竞品 | 发布后编辑 | 改后自动通知 | 状态机 | 防超卖 | 时长编辑 | 审计/留痕 |
|------|-----------|-------------|--------|--------|---------|-----------|
| 到梦空间 | ≈撤销重发，审批繁琐 | 无 | 有 | 有 | 禁区（绑学分） | 有（审批流） |
| 志愿汇 | 编辑受限 | 无 | 有 | 有 | 禁区（绑签到） | 部分 |
| 问卷星/金数据 | 灵活（表单级） | 无 | 无活动状态机 | 无（可超卖） | 不适用 | 无 |
| 钉钉/企微 | 可改且改后自动通知 | ✅ 唯一做到 | 有（会议/日程） | 弱 | 不适用 | 有 |
| 青协自建（群接龙/Excel） | 随意改、零通知 | 无 | 无 | 无 | 随意 | 无 |

**核心结论**：没有一家把"发布后编辑"做透——到梦繁琐、志愿汇受限且无通知、问卷星灵活但无状态机且超卖、钉钉有通知但无活动业务语义、自建全凭自觉。

### 4.2 差异化定位
> **"敢让组织者改、且改得有规矩"** = 编辑自由（对标表单）+ 状态规范（对标到梦/志愿汇）+ 自动通知（对标钉钉）。

### 4.3 六条关键设计启示
1. 分级编辑权限：低风险字段随时改即时生效；高风险字段（名称/时间/地点/时长/人数）需二次确认 + 通知 + 留痕。
2. 人数上限调减防超卖：已报名 > 新上限时禁止直接生效，先处理超员或转候选。
3. 活动开始前 24h 锁定关键字段，展示"最后可改时间"倒计时。
4. 修改后自动通知已报名者（含差异高亮 + 退出报名入口）。
5. 版本记录 + 审计日志（谁/何时/字段 X→Y/是否通知）。
6. 时长修改与签到解耦保护（历史已认证数据不可被普通编辑覆盖）。

## 5. 数据指标（来自数析）

### 5.1 试点口径
20 所高校 × 每校 6 个活跃组织者 × 3 个月（≈13 周）。

### 5.2 供给侧指标速览表

| 指标 | 参考目标 |
|------|---------|
| 活动发布数 | 周均 ≥ 2 / 校 |
| 发布者活跃率 | 首月 ≥ 30% → 第 3 月 ≥ 50% |

| 编辑频率分布 | 中位数 1–2 次/活动；≥ 4 次 ≤ 15% |

| 招募转化率 | 中位 ≥ 80% |
| 满员率 | 25%–45% |
| 活动取消率 | ≤ 5% |
| 认证时长供给量 | 随发布数线性增长（看趋势） |
| 履约-认证衔接率 | ≥ 70% |

### 5.3 埋点事件
- **activity_create**（organizer_role / title / duration_hours / headcount_limit / positions / location / event_time / signup_deadline / is_direct_publish / template_id / draft_id）
- **activity_edit**（editor_role / field_name / old_value / new_value / edit_seq / time_since_publish；field_name 枚举 name / event_time / duration_hours / headcount_limit / position / location / signup_deadline / description）

| R29 | 活动开始后锁定核心字段（时长/人数/岗位/签到方式，确需改走校方审批）｜扩展 | P0 | Given 活动已开始，When 编辑核心字段，Then 被锁定并提示走校方审批；说明性字段仍可改 | 3 |
| R30 | 防超卖（人数上限调减，已报名 > 新上限则禁止直接生效）｜扩展 | P0 | Given 已报名 45、新上限 40，When 提交调减，Then 被阻断，须先将 5 人转候补/退出后方可生效 | 3 |

| R32 | 发布前预览（所见即所得预览）｜扩展 | P2 | Given 填表完成，When 点预览，Then 以学生视角渲染活动页，确认后再发布 | 2 |

**估算合计**：约 49 人日（P0 33 人日，P1 11 人日，P2 5 人日）。

## 7. 活动状态机

```
                ┌────────────┐
    新建/存草稿 │   草稿     │◄──────── 编辑后存草稿
                └─────┬──────┘
                      │ 发布（校验通过）
                      ▼
             ┌─────────────────┐
             │  已发布 / 招募中  │◄──────── 编辑（低/高风险分级+通知）
             └───┬───────┬─────┘
       满员(报名≥上限)│       │ 报名截止时间到
                 ▼       ▼
           ┌────────┐ ┌────────────┐
           │  已满   │ │ 报名截止    │
           └───┬────┘ └─────┬──────┘
       名额释放/调增  │       │
                 ▼   ▼
             ┌─────────────┐
             │   进行中     │◄──── 核心字段锁定，仅改说明性字段
             └──┬───────┬──┘
        正常结束 │       │ 取消（任意招募/进行中状态可触发）
                 ▼       ▼
          ┌─────────┐ ┌─────────┐
          │  已结束  │ │ 已取消   │（记录保留，不可再报名）
          └─────────┘ └─────────┘
```

### 各状态允许的编辑操作（白名单）

| 状态 | 可编辑字段 | 可执行动作 | 禁止动作 |
|------|-----------|-----------|---------|
| 草稿 | 全部字段 | 存草稿、发布、删除 | — |
| 已发布/招募中 | 全部字段（分级 + 二次确认 + 通知） | 编辑、暂停报名、取消、调名额 | — |
| 已满 | 人数上限（增/减防超卖）、说明性字段 | 释放名额、转候补、取消 | 报名（面向学生） |
| 报名截止 | 说明性字段；确需改核心走审批 | 查看名单、取消 | 学生报名 |
| 进行中 | 仅说明性字段（描述/联系方式/说明） | 取消（走审批/留痕） | 时长/人数/岗位/签到方式/时间地点 |
| 已结束 | 不可编辑 | 导出名单、发时长/证书、归档 | 编辑、取消 |
| 已取消 | 不可编辑（只读留痕） | 查看记录、复制为新活动 | 报名、编辑 |

## 8. 字段与编辑分级规则表

### 8.1 发布字段清单

| 字段 | key | 类型 | 必填 | 校验 |
|------|-----|------|------|------|

## 9. 关键流程

### 9.1 发布流程
```
组织者进入发布页
  → 选择「空白新建」/「从模板创建」/「从草稿恢复」
  → 填写/编辑 12 字段（预填+智能提示辅助）
  → [可选] 存草稿 → 草稿箱
  → [可选] 发布前预览（学生视角）
  → 提交 → 字段校验
       ├─ 校验失败 → 定位红显、阻断
       └─ 校验通过 → 创建活动 → 状态=已发布/招募中 → 埋点 activity_create
```

### 9.2 编辑 + 二次确认 + 通知流程
```
组织者对「已发布」活动发起编辑
  → 判断字段风险级
       ├─ 低风险（描述/封面/联系方式/说明）→ 直接保存 → 即时生效 → 留痕（无需通知）
       └─ 中/高风险（名称/时间/地点/时长/人数/岗位/截止/签到）
             → 活动是否已开始？
                  ├─ 已开始 → 核心字段锁定 → 提示走校方审批 → 结束
                  └─ 未开始 → 二次确认弹窗（字段 X→Y；"将通知 N 名已报名学生"）
                        → 确认保存 → 生成版本记录 + 审计日志
                        → 判断通知档（强制/轻量/无需）
                             ├─ 强制 → 全员通知（差异高亮 + 退出报名入口）→ 追踪回执
                             └─ 轻量 → 通知（无回执要求）
                        → 埋点 activity_edit
                        → 涉及人数调减 → 防超卖校验（已报名>新上限则阻断）
```

### 9.3 取消流程
```
组织者对「招募中/已满/报名截止/进行中」活动发起取消
  → 填写取消原因（必填）
  → 二次确认（"将通知 N 名已报名学生 + 该操作不可逆"）
  → 确认 → 状态置「已取消」
  → 全员强制通知（含取消原因）
  → 留痕：cancel_reason + enrolled_count_at_cancel 埋点 activity_cancel
  → 活动记录保留只读（名单/编辑历史仍可查），不物理删除
```

## ⚠️ 待确认 / 假设 / Non-goals

**待确认（7 项开放问题）**：
1. 校方审批触发门槛：哪些字段、多大改动幅度触发审批？审批人/流/SLA？
2. 时长-签到解耦边界：已报名未签到者时长下调是否也需审批？已认证是否彻底锁定？
3. 同组织管理者边界：学校/学院/社团三级继承规则与审计归属？
4. 防超卖超员处置决策权：手动选人 vs 后进先出自动转候补？
5. 回执强制性与时效：是否影响报名有效性？截止时间由谁设定？
6. 通知渠道与成本：是否必须短信/微信服务通知？预算额度？
7. 模板与草稿生命周期：保留周期、容量上限、跨组织共享？

**关键假设**：
- 假设"发布后纠错"是高频刚需（编辑率 20%-40%），若实际远低于此，编辑能力需重新评估投入。
- 假设组织者愿意承担"二次确认 + 通知"的增量操作，否则纠错闭环会因供给端惰性而失效。
- 假设供给侧指标参考值（发布数、编辑率、取消率）需以试点真实埋点回填校准。

**Non-goals（v1 明确不做，详见正文第 10 节）**：不改写历史已认证数据；不做组织者移动端完整后台；不做多人实时协同编辑；不做智能排期/场地冲突检测；不做支付/退款/积分流转；不做取消后自动代报名补录；不做对公众开放的分享预览链接。
